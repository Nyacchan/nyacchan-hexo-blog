一、C 程序的基本骨架

要点

  • #include <stdio.h> 用 scanf / printf 必须有
  • main 是程序入口
  • return 0; 表示程序正常结束（不写也能过，但养成习惯）

二、输入输出 scanf / printf

核心规则

scanf 要地址（&），printf 要值（不用 &）。

为什么？

  • scanf 要往变量里写数据，必须知道变量在哪 → 给地址（&x）
  • printf 只是读变量的值 → 给值（x）

漏掉 & 的后果：程序崩溃 → RE（踩过三次）

数组是例外

多组数据的读法

⚠️ 数清楚题目给了几组数据 —— 多读一次会吃掉后面的数据，全盘错位。

⚠️ 最容易错的点

double 在 scanf 里用 %lf，在 printf 里用 %f！

原因：printf 会把 float 自动提升为 double，所以不用区分；scanf 拿到的是指针，必须区分。

⚠️ 小数位数 vs 有效数字

题目说"保留 6 位有效数字" → 用 %g；说"保留 6 位小数" → 用 %.6f。

⚠️ cout 和 printf 的默认精度不同

题目里说"用 cout 输出"时，cout 输出 double 默认是 6 位有效数字（相当于 %g），不是 printf("%f") 的 6 位小数。

⚠️ %.1f 和 %.lf

1 是数字一，l 是小写字母 L —— 长得太像，极易看错。

题目输出最后一行通常不加 \n，多一个都可能 WA。（B2005 就栽在这）

但题目明说"用换行符隔开"时，就要加。

五、运算陷阱

⭐ 陷阱 1：整数除法（踩过 5 次以上！）

规则：只要算式里有小数，参与运算的数就必须至少有一个是浮点类型。

三种修法

⭐ 陷阱 2：运算符优先级与结合性

* / % 同级，从左往右算；想改变顺序只能加括号。

⭐ 陷阱 3：向上取整 / 向下取整

场景方向写法
至少需要几个（不够也进位）向上(a + b - 1) / b
最多能买几个（不够就舍）向下a / b

例 1：走路 10 米，速度 3 米/分 → (10 + 3 - 1) / 3 = 4 分钟

例 2：需要 57 支铅笔，每包 30 支 → (57 + 29) / 30 = 2 包

原理：+ b - 1 是先垫高一点，让除不尽的情况也能进位，除得尽时又不会多加。

⭐ 陷阱 4：浮点数不要用 == 比较

能转成整数比较就转 —— 比如三角形判定用 a*a + b*b == c*c，全程整数，绝对精确。

⭐ 陷阱 5：== 和 = 写错（踩过两次）

编译器可能只给警告，不报错。 防御写法：if (4 == t)（写错会立刻报错）

⭐ 陷阱 6：整数溢出

类型范围

⭐ 擂台初始值要"够大"，但不是"越大越好" —— 要按题目范围估算上界。

原理：反复用"除数变被除数，余数变除数"，直到余数为 0，此时的被除数就是 GCD。

例：gcd(12, 8) → (8, 4) → (4, 0) → 返回 4 ✔️

十二、循环结构（【入门3】核心）

【入门3】21 题全 AK 之后，循环这块的所有套路基本都见过了。这一章是重点。

12.1 两种循环的等价关系

while 和 for 写法能互相转换，先看对照：

初始化条件自增
while循环前单独写while (...)循环体里自己写
for第一段第二段第三段（自动执行）

⭐ 核心认知：for 只是把"初始化 / 条件 / 自增"三个位置固定下来的 while。

12.2 for 三段的铁律

  • 三段之间用分号 ; 隔开，不是逗号！（这个坑踩了 4 次以上）
  • 三段都可以为空，但分号不能省：for (; a > 1; day++)
  • 在 for 里声明 int i，出了循环就不能用了

12.3 ⭐ 循环条件到底怎么写

心法：循环条件 = “什么情况下我还得继续干”，而不是"我想看到什么结果"。

对比一尺之棰（P5720，每次除以 2 直到变成 1）：

判断标准：问自己"最后一次循环开始前，变量的值应该是什么"。

12.4 ⭐ 自增只能在"一个地方"

day++ 不是越多越好，而是每次循环必须恰好加一次。

for 提供了"自动响铃的位置"，while 没有，得自己按。

12.11 ⭐ 拆数字（数位运算）

【入门3】最重要的通用技能，P1980 / P1307 / P1217 都用它。

心法：先看后扔。

用途写法
统计某数字出现次数if (digit == x) cnt++;
数字反转rev = rev * 10 + t % 10;
判回文反转后 rev == n
数位求和sum += t % 10;

⚠️ 负数要特殊处理：-123 % 10 == -3（C 向 0 取整），所以负数要先存符号、转正数处理、最后补回符号。

12.12 ⭐ 自己跟"上一个"比（最长连号）

P1420 最长连号：序列里最长的连续递增子串长度。

⚠️ 这类题的顺序绝对不能动，不能先排序（排完序答案就错了）。

12.13 ⭐ 回文质数（P1217 满分做法）

关键数学结论：除 11 以外，所有偶数位长度的回文数都是 11 的倍数，必定不是质数。

所以在 1e8 范围内，只需考虑 1 / 2 / 3 / 5 / 7 位回文，4 / 6 / 8 位全跳过。

思路转换：不要枚举所有数判回文，而是"构造回文数"。

效率对比：暴力遍历 1e8 个 ~ 要跑几十秒；构造法0.2 秒（779 个回文质数）。

12.14 枚举倒着来（Davor）

题目要求"X 最大"时，从大到小枚举，第一个找到的就是答案。

P4956 Davor：364X + 1092K = N，求 X 最大、K 最小的解。

⚠️ 三个坑：

  1. last > 0 不能写 >= 0（K 必须为正）
  2. 先判正再取模（负数取模在 C 里结果可能为负）
  3. 别把方程当赋值语句写（n = 364 * x + 1092 * k; 会毁掉 n）

十三、代码风格

缩进（Python 感的来源）

规律

  • { 跟上一层对齐，或独占一行
  • 每深一层多 4 个空格
  • 用空格不用 Tab（网页 IDE 里 Tab 会错位）

空行分组 ⭐

用空行把"读入 / 计算 / 输出"分成块 —— 这才是看着舒服的关键。

空格规则

逗号/分号前面不加空格，后面加一个；运算符两边各一个空格。

危险运算要放在安全分支里 ⭐

曾经把 s / t 写在 if 前面 → t = 0 时直接崩。

⭐ 规则：可能出错的运算（除零、开负数根、越界），必须先确认条件安全再执行。

⚠️ C 的分号规则（从 Python 转过来必看）

位置要不要分号
普通语句（scanf / printf / x++）要
for 三段之间要（两个分号）
if (...) 后面不要
else 后面不要
{ 和 } 后面不要

  • 举 2~3 个具体例子手动推一遍，规律自己会冒出来

检查说明

2. == vs =条件里写的是两个等号吗？运算符打对了吗？

边界测试 ⭐

别只用样例测，想想极端情况：

  • t = 0？（除零）
  • 结果为负？（要不要归零）
  • 数据超范围？（溢出）
  • 并列的情况？（取靠前还是靠后）
  • 空输入 / 单个元素？

缩写全称含义常见原因
ACAccepted通过—
WAWrong Answer答案错逻辑错、格式错、精度错
RERuntime Error运行崩溃漏 &、数组越界、除以 0
TLETime Limit Exceeded超时算法太慢
CECompile Error编译失败语法错误
MLEMemory Limit Exceeded内存超限数组开太大

⭐ 关键认知

OJ 报的是"最终状态"，不是"bug 清单"。
一个 WA 背后可能藏着好几个错误，改完一个还有下一个。

所以修 bug 是循环：改 → 交 → 看结果 → 改 → 交。

⚠️ 而且"能跑"≠"对"：

  • 语法全对、类型全对、逻辑大体对 → 编译通过，大部分情况结果正确
  • 所以它交出的是"看起来合理但错的答案" —— 这是最难查的一类 bug

看报错信息

CE 时编译器会告诉你：

直接就是答案。 越是新手越该认真读报错。

警告也要看：

“定义了但没用” —— 常常正好指出你写错了变量名。

下载/查看测试数据，对比"我的输出 vs 标准输出" —— 逐字符看，差在哪立刻就知道，比猜准一百倍。

十六、常用套路总结

套路 1：统一单位

时间/钱/长度加减，先统一到最小单位，算完再换回来。

好处：避免"借位"的麻烦。

套路 2：打擂台（找最大/最小）⭐

这是最常用的框架之一。

⚠️ 两个坑：

  • > 还是 >= —— 决定"并列时保留靠前还是靠后"（题目常要求"并列取靠前的"→ 用 >）
  • 初始值 —— 找最小要设"足够大"的数，但不能大到溢出

套路 3：枚举 + 打擂台（多方案取最优）

“几种方案各算一遍，取最便宜/最快”：

注意：不是"单价最低就最省" —— 要按实际方案算总价。

套路 4：先排序再判断

排完序后，很多条件能大幅简化。

排序带来的简化：

  • 三角形判定：只需检查 a + b > c（不用判断 3 组）
  • 角度判定：直接比较 a² + b² 和 c²（不用找最长边）
  • 等腰判定：只需 a == b || b == c（不用写 a == c）

⚠️ 三次比较的顺序是 ab → bc → ab，第三次不能省（否则中间被打乱的最小值回不到最前）。

套路 5：桶计数（数组当下标）

把 26 个 if 变成一行。

套路 6：字符 ↔ 数字

套路 7：倒推

“经过一系列操作到达某个状态，问初始状态” → 从已知终点倒着推。

逆向运算：加变减、减变加、乘变除、除变乘，顺序也要倒过来。

例子（猴子吃桃）：正向是 ÷2 - 1，逆向就是 +1 ×2。

套路 8：把数学式翻译成 C

老老实实按运算符优先级加括号：

⚠️ 根号/分母罩住的范围，括号必须全部包住。

套路 9：递推代替公式（循环类）⭐

“每一步是上一步的某个比例 / 加某个量” → 用循环递推，别用数学公式。

好处：误差小、不用 math.h、O(1) 空间。

套路 10：打擂台不一定要数组

边读边比，一次遍历就出结果，不用存数组。

套路 11：求和后减去最值（避免重复值踩坑）

"去掉一个最大值、一个最小值"这类题，用减法比用标记法安全。

⭐ 为什么比标记法好？ 有多个相同最大值时，sumAll - mx - mn 只会减掉一个最大和一个最小，正好符合题意。

套路 12：模拟规则，一步一步照做

题目把规则写清楚了，就老老实实按顺序模拟，不要想太多。

⚠️ 顺序极其重要：先判断钱够不够，再存钱，最后扣花销。顺序错了全盘皆输。
